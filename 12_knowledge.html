Reference implementation knowledgebase

This notebook stores favourite implementation repositories in one local LanceDB database. It keeps registered sources, indexed README/module/function/class/method records, and direct same-repo caller/callee links for examples an agent can inspect before writing similar code.

Library searches inspect the target workspace before looking for a version. A relevant installed direct dependency uses its exact version, downloads that public PyPI release only when it is missing, then parses notebooks for nbdev projects and Python files for other projects. The index reuses embeddings for unchanged file hashes and keeps only the newest three indexed versions per package.

Production contract

Reference knowledge is explicit and local. It registers repositories, ingests Python and notebook implementation records, preserves dependency and branch context, and returns structured examples through one query path.

Imports

Reference indexing uses filesystem scans, Python AST parsing, notebook reads, LanceDB storage, and sentence-transformers embeddings.

Reference implementation knowledgebase

The reference knowledgebase stores favourite implementation repositories in one local LanceDB database. It keeps three tables: reference_repos for registered sources, reference_items for README/module/function/class/method records, and reference_edges for direct same-repo caller/callee links.

This feature requires both LanceDB and sentence-transformers. Ingestion writes a full sentence-transformers vector for every indexed item, and queries combine structured filters, LanceDB full-text search, and vector similarity over that searchable vector store. If either dependency or the configured embedding model is unavailable, reference ingestion/querying fails clearly instead of falling back to a weaker embedding.

The public workflow is:

  1. reference_add(...) registers a local path or GitHub repository.
  2. reference_ingest(...) clones with gh repo clone when possible, extracts Python and notebook symbols, and writes LanceDB rows.
  3. reference_query(...) returns examples, dependency status, optional branch context, and increments each returned item’s returned_count.

Reference knowledge examples below use tiny local fixtures. They document the public API without touching the global user database.

Retrieval and relevance

The search layer combines metadata filters, lexical search, vectors, and small domain rules. The rules matter because a query for a specific helper should not be promoted by an unrelated generic name.

Specific reference relevance

reference_query separates exact identifier intent from generic query fragments. A hit must cover the specific terms of a multi-concept request; otherwise it is reported as low confidence instead of being promoted by an incidental symbol component.

Problem-solution memory

Each new pair needs at least four distinct namespaced tags from topic, sub-topic, library, problem-category, and solution-category. Records also keep the repository, commit, verification command, and verification time.

Queries keep tag filtering exact. Hits report matching tags and score components. A query with no exact match reports the miss, counts broader candidates, and suggests available tags instead of returning a loose match.

Problem-solution memory

Problem memory records a reusable observation beside the source-code index. It is separate from reference retrieval because an agent may need a prior decision even when no code example is relevant.

Retrieval Experiments

This small experiment compares four search surfaces on a tiny structured corpus:

  • tags_fts: LanceDB full-text search over tags plus symbol/doc text, with no vector similarity.
  • docstring: vector similarity over docstrings only.
  • signature_doc_return: vector similarity over the signature, docstring, and return statements.
  • full_body: vector similarity over the whole indexed source block.

The expected symbols mirror common fastcore lookups: store_attr, patch, and compose.

Retrieval experiments

The experiment compares searchable representations on a tiny fixed corpus. It is kept separate from the production query path so it can explain the tradeoff without changing query behavior.

def _experiment_returns(source):
    try: tree = ast.parse(source or "")
    except SyntaxError: return ""
    vals = []
    for node in ast.walk(tree):
        if isinstance(node, ast.Return) and node.value is not None:
            try: vals.append(ast.unparse(node.value))
            except Exception: pass
    return "\n".join(vals)
def _experiment_text(row, mode):
    if mode == "docstring": return row.get("docstring", "")
    if mode == "signature_doc_return":
        return "\n".join([row.get("signature", ""), row.get("docstring", ""), _experiment_returns(row.get("source", ""))])
    if mode == "full_body": return row.get("source", "")
    return " ".join([*(row.get("tags") or []), row.get("symbol", ""), row.get("signature", ""), row.get("docstring", "")])
def _experiment_table(home, rows, mode):
    table_rows = []
    for row in rows:
        text = _experiment_text(row, mode)
        table_rows.append({**row, "search_text": text, "vector": _reference_vector(text)})
    table = _reference_db(home).create_table(f"reference_experiment_{mode}", data=table_rows, mode="overwrite")
    try: table.create_fts_index("search_text", replace=True)
    except Exception: pass
    return table
def _experiment_search(table, query, mode, top_k=3):
    if mode == "tags_fts":
        rows = table.search(query, query_type="fts").limit(top_k).to_list()
    else:
        rows = table.search(_reference_vector(query)).metric("cosine").limit(top_k).to_list()
    return [row["symbol"] for row in rows]

Version-aware sources

A relevant direct dependency is indexed at the version the target workspace uses. Public PyPI downloads are only a fallback when that exact source is not already available.

Reusing local repositories

reference_discover stores reference roots and registers Git repositories at the root or one directory below it. Local names include a path hash, so two repositories with the same folder name remain separate.

Local repository discovery

Discovery only registers Git repositories at configured roots. Limiting the scan to roots and their direct children keeps a background index from unexpectedly walking an entire home directory.

Workspace versions and upstream proposals

reference_query asks the target workspace’s virtual environment which distributions are installed. It only downloads public source for a relevant package, so returned code can match the version the project already uses. reference_propose writes review material only; it never creates a fork or pull request.

Small public examples

reference_home is deliberately simple. It makes the storage location explicit, which is useful when an agent needs an isolated database for a test or a workspace-specific index.

Query planning

_query_feature_plan makes the non-obvious parts of retrieval visible before any database work starts. It records the requested evidence, likely implementation kinds, and the search passes that will be applied.

_query_feature_plan("find a FastHTML route test")

The focused check keeps the public storage location and query-intent classification stable without requiring LanceDB, a model, or a repository fixture.

Lazy embedding dependency

Sentence-transformers is imported only when vector search is needed. That keeps registry and metadata commands usable without loading a model at module import time.
